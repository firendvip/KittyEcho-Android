# 弦外小猫 Android 输入法 · 阶段2 测试用例 · 第3轮（句首前切修复验证）

- **被测工程**：KittyEcho-Android（FlorisBoard fork 中文输入法）
- **本轮目标**：定点验证「句首前切」修复效果 + 850ms 护栏引入的回归面 + R2 已修项抽验 + P0 冒烟。
- **本轮修复实现要点**（用例设计依据，来自当前源码）：
  1. **开麦/提示音顺序反转**：`VoiceViewModel.startRecording()` 先 `speechEngine.start(...)` 再 `toneController.startBeep(...)`——提示音输出流与录音通路建立若同时发生，vivo audioserver 会让 AudioRecord 首帧延迟数秒、句首被吞（原前切 bug）。顺序敏感，源码有勿改回注释。
  2. **850ms 采集层护栏**：`VoiceViewModel.TONE_GUARD_MS = 850L`；提示音开启时 `speechEngine.start(850)`，关闭时 `start(0)`。`RealSpeechEngine.start()` 换算为 `skipLeadingSamples`（850ms×16kHz=13600 样本）传给 `PcmRecorder.start()`；采集线程按样本把录音开头这段**完全丢弃**——不进兜底缓冲、不进流式 onChunk 队列，喵叫绝不进识别器。真机标定：600ms 必漏、700ms 偶漏、850ms 全覆盖。
  3. **音源锁定 MIC**：`PcmRecorder` 用 `MediaRecorder.AudioSource.MIC`（勿换 VOICE_RECOGNITION——vivo 前端降噪慢收敛会把每句开头 ~2s 静音掉，源码有警告注释）。
  4. **诊断插桩**：`PcmRecorder` 首个有效帧打 `first frame after Xms`（startRecording→首帧窗口即系统层丢声窗口）；`RealSpeechEngine` 首个非空 partial 打 `first partial: …`。
- **改动文件**：`voice/VoiceViewModel.kt`、`speech/PcmRecorder.kt`、`speech/SpeechEngine.kt`、`speech/RealSpeechEngine.kt`。
- **环境标注**：【模拟器可测】= AVD 即可判定（含 logcat/dumpsys）；【须真机】= 依赖真实语音出字/声学时序/vivo 通路行为（首选 vivo iQOO 8 V2136A，即原 bug 复现机）。
- **通用前置**（除非另述）：最新修复版 debug APK 已安装（包名 `com.wordtaker.keyboard.debug`）；已启用并切为默认输入法；麦克风权限已授予；内置模型就位（`files/zipformer-zh/` 4 文件）；提示音开启（除非用例另述）；处于可输入 App 文本框。
- **观察手段**：`adb logcat -v epoch -s VoiceVM RealSpeechEngine PcmRecorder`；真实语音链路可用 Mac `say -v Tingting "<句>"` 扬声器→手机麦克风（同 R1/R2 报告方法，跨设备时钟偏移需校正）。
- **判定基线**（来自 phase2-voice-testrun-device.md 修复前实测）：首字延迟中位 1.86s、3/18 句离群 4.5–11.6s 前切；喵叫尾巴曾解码成「什么/嗯/所」垃圾前缀并提前触发 endpoint。

## 一、定点：句首完整率（句首字多样）

### R3-001 爆破音开头句首完整 — P0【须真机】
- **前置**：通用前置。
- **步骤**：分 6 轮播报/朗读爆破音（b/p/d/t/g/k）开头句，每轮等喵叫播完（约点后 0.9s）再开口：「北京今天天气怎么样」「帮我把灯打开」「大家下午三点开会」「天气预报说明天下雨」「关掉客厅的空调」「快递已经放在门口了」。逐句核对上屏文本。
- **预期**：6/6 句句首字完整（首字不丢、不被替换）；无一句前段整体缺失；CER 与修复前干净基线（≈4.8%）相当或更好。

### R3-002 鼻音/边音开头句首完整 — P0【须真机】
- **前置**：通用前置。
- **步骤**：分 5 轮朗读鼻音/边音（n/m/l/r）开头句：「明天早上八点提醒我」「你好请问现在几点」「拿一杯温水过来」「麻烦把窗户关上」「李老师让我们交作业」。逐句核对上屏文本。
- **预期**：5/5 句句首字完整；鼻音弱起音不被护栏或首帧延迟吞掉。

### R3-003 数字开头句首完整 — P0【须真机】
- **前置**：通用前置。
- **步骤**：分 4 轮朗读数字开头句：「三千五百块钱够不够」「二零二六年七月十五号出发」「百分之二十五的折扣」「一万二千人参加了活动」。逐句核对上屏文本。
- **预期**：4/4 句首个数字完整识别（对照修复前 round8「请在十月十五号…」仅剩后半句的前切样态，不再出现）；数字串内部错字按 CER 常规评估，不算前切。

### R3-004 首字延迟无 >3s 离群 — P0【须真机】
- **前置**：通用前置；logcat `-v epoch` 采集 `PcmRecorder: first frame after Xms` 与 `RealSpeechEngine: first partial`。
- **步骤**：连续 20 轮标准句（如「今天天气不错我们出去走走」），每轮记录：a) `first frame after Xms` 值；b) 播放开始→首个 partial 的首字延迟。统计分布。
- **预期**：a) 20/20 轮 first frame ≤ 500ms（无数秒级首帧延迟——顺序反转的直接观测量）；b) 首字延迟中位 ≤ 2.2s 且 **0/20 轮 > 3s**（修复前 3/18 句 4.5–11.6s 离群应消除）；c) 无整轮无声（0/20）。

### R3-005 喵叫不被识别成垃圾字 — P0【须真机】
- **前置**：通用前置；提示音开启。
- **步骤**：10 轮录音，每轮等喵叫播完后再正常说一句话；逐轮核对：a) 最终上屏文本开头；b) 录音中字幕（partial）的起始内容。
- **预期**：10/10 轮最终文本与 partial 均**无**「什么/嗯/所」等喵叫解码垃圾前缀；partial 首字即真实语音首字（护栏在采集层生效，喵叫样本不进识别器）。

### R3-006 喵叫后的停顿不提前截句 — P0【须真机】
- **前置**：通用前置；提示音开启。
- **步骤**：5 轮：点开始 → 喵叫播完后**再静默约 0.8s** 才开口说完整句（总计开口前静默期 < rule2 1.2s 追加余量的临界情形）→ 观察是否在开口前就 `endpoint detected -> auto stop`。
- **预期**：5/5 轮 endpoint 不在开口前触发（修复前喵叫垃圾字+其后停顿会提前触发 endpoint 截断整句）；整句完整上屏，不提前定稿。

### R3-007 开麦→提示音顺序与首帧日志验证 — P1【模拟器可测】
- **前置**：通用前置；logcat 采集 VoiceVM/PcmRecorder。
- **步骤**：点「点击说话」3 轮，核对每轮日志时序：`startRecording: phase=Recording`（在 speechEngine.start 之后打出）与 `PcmRecorder: first frame after Xms`；同时听感/AudioFlinger 确认喵叫仍正常播放。
- **预期**：每轮均先建立录音通路再播提示音（first frame 日志存在且数值合理）；喵叫每轮恰播 1 次不缺失；无 `start failed` / `capture loop failed` 异常日志。

## 二、修复回归面：850ms 护栏

### R3-010 极快开口（喵叫未播完就抢话） — P0【须真机】
- **前置**：通用前置；提示音开启。
- **步骤**：5 轮：点开始后**立即开口**（不等喵叫播完，开口落在 0–850ms 护栏窗口内）说「马上出发别迟到了」等句；核对上屏文本与丢字位置。
- **预期**：护栏窗口内（≤850ms）的语音按设计被丢弃——句首可能缺 1~2 字，属**已知权衡**（喵叫即「开始说话」提示，正常用户在 0.9s 喵叫听完后开口）；验收线：850ms 之后的语音必须完整识别、不整句丢失、不崩溃；记录实际丢字数供产品评估（若普遍丢 >3 字或整句丢失则判 FAIL）。

### R3-011 提示音关闭时护栏为 0（立即开口句首完整） — P0【须真机】
- **前置**：通用前置；设置中**关闭**提示音。
- **步骤**：5 轮：点开始后立即开口（无喵叫等待）说「零点护栏立即说话测试」等句首多样句；核对句首完整性与日志（此路径 `speechEngine.start(0)`，skipLeadingSamples=0）。
- **预期**：5/5 轮句首字完整（无 850ms 丢弃、也无提示音输出流竞争——本就无提示音）；全程无喵叫、无结束音；识别正常上屏。

### R3-012 连续多轮护栏每轮生效 — P0【须真机】
- **前置**：通用前置；提示音开启。
- **步骤**：连续 10 轮完整录音（自动 endpoint 与手点结束混合），每轮等喵叫播完再说话；逐轮核对：a) 文本无喵叫垃圾前缀；b) 句首完整；c) 轮间无状态残留。
- **预期**：10/10 轮护栏均生效（每轮 `recorder.start()` 重新计数，skip 从 0 样本重新累计——不存在「只有第一轮丢弃」或「后续轮多丢」）；partial 每轮从空开始；内存无异常增长。

### R3-013 手点提前结束在 850ms 内（极短录音） — P1【模拟器可测】
- **前置**：通用前置；提示音开启。
- **步骤**：点开始 → 在 **850ms 内**快速再点一次（手点结束，录音时长短于护栏窗口）→ 观察 UI 与日志；重复 3 次。
- **预期**：所有样本被护栏丢弃 → ASR 返回 blank → toast「未识别到语音」→ 复位 Idle；不卡「处理中」、不崩溃、不上屏、不写历史；结束音正常（与开始音成对）；下一轮可正常录音。

### R3-014 endpoint 自动定稿路径护栏一致 — P1【须真机】
- **前置**：通用前置；提示音开启。
- **步骤**：3 轮：等喵叫播完说一句话后**保持静默**，等 rule2 尾静音自动定稿（不手点）；核对最终文本开头。
- **预期**：自动定稿路径与手点路径的最终文本一致无喵叫垃圾前缀（护栏在采集层按样本丢弃，与定稿方式无关）；`endpoint detected -> auto stop` 由真实语音尾静音触发、时点正常（中位 ~1.9s）。

### R3-015 护栏窗口内取消 — P2【模拟器可测】
- **前置**：通用前置；提示音开启。
- **步骤**：点开始 → 500ms 内点「取消」→ `dumpsys audio` / appops 查麦克风占用 → 再开一轮正常录音。
- **预期**：即时停录，麦克风释放（无 MIC 活跃 session）、回 Idle、结束音播放；无崩溃、无 `release failed` 日志；下一轮录音与护栏行为正常。

## 三、R2 已修项抽验（新开麦顺序不引入回归）

### R3-020 录音中 Home 切走即停录（幽灵录音兜底） — P0【模拟器可测】
- **前置**：通用前置；提示音开启。
- **步骤**：点开始进入录音态（让喵叫播完）→ 按 Home 回桌面 → 等 10 秒 → `dumpsys audio` + `appops get com.wordtaker.keyboard.debug RECORD_AUDIO` 查占用与日志。
- **预期**：与 R2-001 相同：立即 `stopRecordingAndEndTone: discarded recording, reset to Idle`；麦克风 10 秒内无活跃 MIC session；结束音播放；不上屏不写历史（先开麦后播音的新顺序不影响兜底时序）。

### R3-021 护栏窗口内切走（开麦极早期打断） — P1【模拟器可测】
- **前置**：通用前置；提示音开启。
- **步骤**：点开始 → **800ms 内**（喵叫尚在播、护栏未走完）按 Home 切走 → 查麦克风释放与日志 → 回原 App 唤起键盘再录一轮。
- **预期**：兜底同样即时生效：停录、释放 AudioRecord、复位 Idle；无 `capture loop failed` 之外的异常、无幽灵录音；再唤起后键盘待机干净，新录音（含护栏）行为正常。

### R3-022 开始/结束音成对 + 提示音开关约束 — P1【模拟器可测】
- **前置**：通用前置。
- **步骤**：a) 提示音开启：完整一轮（开始→说话/静默→手点结束），核对 AudioFlinger 混音爆发次数；b) 提示音关闭：重复同路径。
- **预期**：a) 开始音+结束音各恰 1 次成对（顺序反转后 startBeep 仍每轮必播、不因先开麦被吞）；b) 全程 0 次爆发，且此时护栏为 0（联动 R3-011 的 `start(0)` 路径）。

## 四、冒烟

### R3-030 正常语音全链路（说话→定稿→润色→上屏） — P0【须真机】
- **前置**：通用前置；网络可用（云端润色）。
- **步骤**：等喵叫播完说「嗯那个我想说的就是这个方案整体上可以细节还要再讨论」→ 尾静音自动定稿（或手点）→ 观察润色与上屏 → 查历史记录。
- **预期**：录音中字幕流式增长；`polish: success` 润色文上屏至光标处；`history: written`（raw+polished 成对入库）；结束音播放；回 Idle 后进入 Success 猫动画；全程无崩溃无卡顿。

### R3-031 键盘打字回归 — P0【模拟器可测】
- **前置**：通用前置；切到拼音打字面板。
- **步骤**：拼音输入「nihao」选候选「你好」上屏 → 删 1 字 → 再输入英文/数字混合 → 切回猫面板再切回打字面板。
- **预期**：打字、候选、删除、面板切换全部正常（本轮改动仅语音链路 4 文件，键盘路径零影响）；无 ANR、无输入错乱。
