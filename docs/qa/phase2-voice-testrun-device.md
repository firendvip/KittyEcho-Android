# 弦外小猫 Android 输入法 · 阶段2（语音一体化）· 真机验证报告

- **执行方式**：真机实测（非模拟器、非只读代码），本机 Bash+adb 亲自驱动。
- **被测设备**：**vivo iQOO 8（V2136A）** · Android **14**（OriginOS build `PD2136_A_9.12.5`）· arm64-v8a · 序列号 15538279400010Z。
- **被测构建**：`KittyEcho-0.35.5-debug`（versionName `0.35.5-debug+e359262`），全量 `:app:clean :app:assembleDebug` 出包，`adb install -r -g` 装机，`ime enable/set` 切为默认输入法，已授麦克风权限。
- **内置模型**：`files/zipformer-zh/` 4 文件就位（encoder.int8.onnx 70.1MB / decoder 1.3MB / joiner 1.0MB / tokens.txt 18.6KB），首启 assets 自动安装完成。
- **真实语音链路**：Mac `say -v Tingting "<句>"` 从扬声器播出 → 手机麦克风收音（系统音量 70%）。**所有 CER/延迟均含「扬声器→空气→手机麦克风」声学链路损失，为真机端到端参考值，非纯 ASR 引擎理论值。**
- **插桩**：为测「首字延迟」在 `RealSpeechEngine` 首个非空 partial 处加一行 `Log.i(TAG,"first partial: …")`（QA 用，非功能改动）；logcat `-v epoch` 采时间戳。

## 一、ASR 关键指标（真机实测）

| 指标 | 结果 | 测法 |
|---|---|---|
| **首字延迟**（播放开始→首个 partial 字幕出现） | 中位 **1.86s**，典型区间 1.7–2.1s；偶发 3/18 句飙到 4.5–11.6s（见下「首字前切」发现） | logcat epoch 时间戳：`first partial` 时刻 − 播放起点（跨设备时钟偏移 +0.122s 已校正） |
| **定稿延迟·自动**（句尾静音→endpoint 自动停） | 中位 **1.9s**（rule2 1.2s 静音 + 收尾） | `endpoint detected -> auto stop` − 播放结束时刻 |
| **定稿延迟·手点**（手点结束→ASR 解码完成） | **0.25–0.36s**（手点即刻批量解码） | `ASR result` − 手点时刻 |
| **上屏延迟**（句尾→commitText 含云端润色） | 中位 **3.17s**（润色成功约 +1–1.5s） | `commit emitted` − 播放结束时刻 |
| **CER·干净**（剔除 3 条声学捕获异常后 15 句） | **≈ 4.8%**（12 edits / 249 字） | Levenshtein 字级编辑距离，去标点 |
| **CER·原始**（全部 18 条成功捕获句） | **18.3%**（57/312），被 3 条前切/噪声句拉高 | 同上 |
| **捕获成功率** | 18/20 句成功上屏；2 句未捕获（「好的没问题」超短句 blank；「地铁二号线…」首字延迟 11.6s 前切失败） | — |
| **峰值内存**（识别中 TOTAL PSS） | 峰值 **≈ 383MB**（392372K）；基线 ~352MB，20 轮后收敛 320–330MB，漂移 <35MB，**无会话泄漏** | `dumpsys meminfo` 多次采样 |
| **发热/降频**（连续识别 10min / 50 轮） | 电池温度 **34.4°C→35.6°C（+1.2°C）**；首字延迟首5轮≈末5轮（1.9s，**零劣化**）；内存收敛 ~350MB；**无降频、无 ANR、无崩溃** | `dumpsys battery temperature` + 逐轮首字延迟趋势 |
| **冷启动** | force-stop 后：键盘可见 **≈3.8s**；语音完全可用（点药丸即录）**≈4.4s**；未就绪前点击有 hint 兜底不卡死 | 时间戳测「summon→onStartInputView→录音开始」 |

**发现：首字「前切」偶发。** 20 句中 3 句（round1 噪声化、round8「请在十月十五号…」仅剩「报告发到我的邮」、round9 前半句丢失）首字延迟骤升到 4.5–11.6s，导致句子**前段被吞**。核心引擎对完整捕获句准确率很高（干净 CER 4.8%，13/18 句 CER≤6%、7 句 0 错），说明问题在录音起始/预热瞬间的捕获时序，而非识别精度。建议后续排查「点药丸→AudioRecord 首帧」窗口。数字/长句识别良好（手机号仅错 1 字、「一万二/百分之二十五/三千五百字」基本正确）。
