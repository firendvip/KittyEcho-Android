# 阶段2（语音一体化）测试用例 · 第4轮（音源切换 MIC→VOICE_COMMUNICATION 修复验证）

> **历史用例，整份已退役（2026-07-28）。** 本文保留旧包的设备标定与平台副作用证据，
> 但其中固定句首 PCM 丢弃窗口、录音启动喵叫及相关等待/配对用例均不得用于当前包。
> 当前合同为：开录立即保留并送出全部 PCM，启动仅短震与录音猫；结束喵叫只可在
> 采集冻结、麦克风关闭之后按既有开关与音量策略播放。

- **设计日期**：2026-07-11
- **被测修复**：R3-011（关提示音吞句首）。真因 = vivo MIC 采集通路前端 VAD 门控（听到类语音才开门，无预热时吞句首 ~0.6–2.2s）。修复 = `PcmRecorder` 音源 `MIC` → **`VOICE_COMMUNICATION`**（通话采集通路无门控）；一切预热/可闻声方案已移除；喵叫仅在提示音开启时播放；850ms 护栏保留且**仅在提示音开启时启用**（`start(if (toneOn) TONE_GUARD_MS else 0L)`），关提示音 = 护栏 0 + 全程无声。
- **被测包**：**真机用已装包（07-11 13:59 版），不需重装**；模拟器同版本（若未装该版再装）。
- **真机**：vivo iQOO 8（V2136A）· Android 14（原 bug 复现机）；载体 = 系统笔记 App 文本框。
- **模拟器**：AVD wt_real（API 34）· emulator-5554；载体 = 系统设置搜索框。
- **测试链路纪律（沿承 R3 方法论，判读前必读）**：Mac 外放必须用 **19.5kHz 近超声保活音**防功放门控截头（禁用低幅白噪声保活——会诱发 vivo AGC 幻觉前缀）；抢话/精确时序用预渲染 WAV + `afplay`；跨设备时钟偏移先校正。凡句首判定必须出自清洁链路批次。
- **证据基线**：`logcat -v epoch -s VoiceVM:* RealSpeechEngine:* PcmRecorder:* VoiceTrigger:*`（含 `first frame after Xms` 插桩）+ `wordtaker-history.db` raw 文本 + `dumpsys media.audio_flinger`（Total writes 提示音计数）+ `appops get <pkg> RECORD_AUDIO` + `dumpsys audio`（通路/焦点观察）。
- **R4 特别关注**：VOICE_COMMUNICATION 是**通话采集通路**，系统自带 AEC/NS/AGC，且可能被系统视为「通信中」——本轮除定点验收外，重点回归其平台级副作用（识别质量、音量增益、媒体协同、并发录音、通知音）。

## 优先级说明

- **P0**：修复验收 / 平台副作用可能直接破坏核心体验，必测必过。
- **P1**：重要回归面，应测；失败评估影响后定级。
- **P2**：条件允许则测；不可测时明确标注 SKIP 及原因。

## 一、定点验收：R3-011 静音唤醒（关提示音句首完整）

### R4-001 静音唤醒主验收：关提示音+立即开口句首完整 P0【须真机·已装包 13:59 版】

- **前置**：设置中提示音**关闭**；媒体音量正常（约 50–70%，勿静音——需验证「无声」是修复行为而非音量掩盖）；超声保活链路就绪；logcat 就绪。
- **步骤**：
  1. 光标置笔记文本框，点猫开始说话；
  2. 点击后**立即**（≤0.3s，afplay 预渲染 WAV 即刻播放）说 R3-011 原 FAIL 句集，每句 1 轮共 5 轮：「北京欢迎你的到来」「明年计划去欧洲旅行」「三点半在会议室集合」「帮我把空调温度调高」「快递明天下午才能到」；
  3. 每轮记录：上屏/历史 raw 文本、`first frame after Xms`、首个 partial 内容与时点。
- **预期**：
  - ≥5/5 句**句首字完整**（同音字替换不算丢；缺首 1 字即 FAIL——这是本轮唯一核心验收）；
  - 全程 App 侧无任何提示音（人耳 + AudioFlinger writes 0 增量双重确认）；
  - `first frame` 无数秒级离群（对照 R3 基线 ≤500ms 量级，VOICE_COMMUNICATION 通路允许不同但须稳定且 <1s）；
  - logcat 无 `start failed` / `capture loop failed`。

### R4-002 关提示音·软起音重灾句复测 P0【须真机·已装包 13:59 版】

- **前置**：同 R4-001（提示音关闭）。
- **步骤**：点说话后立即开口，测 R3-011 软起音重灾样本：「零点护栏立即说话测试」×3、「明年计划去欧洲旅行」×2（R3 该类曾仅剩「测试」「去欧洲旅行」）。
- **预期**：5/5 首词完整（「零点」「明年」在句首出现）；无整句空白；首个 partial 为真实语音起始字（无「嗯/什么/所」幻觉前缀）。

### R4-003 关提示音·延迟 1.3s 再开口 P0【须真机·已装包 13:59 版】

- **前置**：同 R4-001。R3 轮此姿势仍 4/5 丢句首（门控不看能量看形态），本轮验证通路级修复对任意开口时机均有效。
- **步骤**：点说话→静默等 1.3s→说「三千五百块钱预算够不够」「二零二六年七月的安排」各 2 轮（数字开头 = 前切最敏感样本）。
- **预期**：4/4 首数字完整；endpoint 不在开口前被静默期误触发（1.3s 静默 < endpoint 尾静音阈值，录音应仍在进行）。

## 二、重点回归：VOICE_COMMUNICATION 平台级副作用

### R4-010 识别质量不劣化（AEC/NS/AGC 通路 CER 抽验）P0【须真机·已装包 13:59 版】

- **前置**：提示音**开启**（正常用户主流形态）；清洁链路；R3 定判批同句集复用（可直接对比）。
- **步骤**：播 R3 已 PASS 的标准句集共 10 句（R3-001 爆破音 6 句：北京/帮我/大家/天气/关掉/快递 + R3-003 数字 4 句：三千五百/二零二六/百分之/一万二千），等喵叫毕再开口；逐句比对 raw 文本。
- **预期**：
  - 字级 CER 不明显劣于 R3 MIC 基线（R3 该批仅 1 处同音错「空调→烹调」；本轮同批错字数 ≤3 且均为同音替换级，无成段丢失/成段乱码）；
  - 若出现系统 NS 抑真人声、AGC 泵效应样态（时有时无的整词丢失、音量忽大忽小相关的错识）→ FAIL 并记录样本。

### R4-011 采集增益/音量变化观察 P1【须真机·已装包 13:59 版】

- **前置**：提示音开启；同一 Mac 播放音量（70）不变，与 R3 批同源同距离。
- **步骤**：
  1. 正常音量播 3 句标准句；
  2. Mac 音量降至 40（模拟小声说话）再播同 3 句；
  3. 观察：识别完整度、首个 partial 时延、是否出现 AGC 幻觉前缀（「嗯/幸运」类，R3 曾标定低幅信号会被 vivo AGC 放大致幻）。
- **预期**：正常音量 3/3 完整；小音量 ≥2/3 主体完整（允许个别同音错）；两档均无幻觉前缀、无提前 endpoint。若小音量整句无声（通话通路 NS 把远场小信号当噪声全抑）→ 记录为产品风险，单独评估。

### R4-012 媒体协同：录音时播音乐的 ducking 与恢复 P0【须真机·已装包 13:59 版】

- **前置**：提示音开启；手机本机用音乐 App（或 `am start` 系统音乐/浏览器播视频）**正在外放播放**；logcat + `dumpsys audio`（audio focus 栈）就绪。
- **步骤**：
  1. 记录播放基线（能听到、音量正常）；
  2. 光标置笔记，点说话→观察音乐是否被压低（ducking）/暂停/无变化；
  3. 说「现在正在放音乐测试协同」→ 等自动定稿上屏；
  4. 观察录完（回 Idle）后音乐是否**自动恢复**原音量/继续播放；
  5. 重复 1 轮用「手点结束」路径。
- **预期**：
  - 上屏文本主体完整（背景音乐下识别允许劣化但不至整句丢失——VOICE_COMMUNICATION 自带 AEC 应有助于回声消除，观察记录即可）；
  - **录音结束后音乐必须恢复**（不永久静音、不被杀）——不恢复即 FAIL；
  - 录音中音乐被暂停（而非 duck）不判 FAIL，但必须如实记录（用户感知差异大，供产品评估）；
  - `dumpsys audio` 焦点栈录后无本 App 残留焦点持有。

### R4-013 蓝牙耳机连接时的 mic 路由 P2【须真机·已装包 13:59 版·可测则测】

- **前置**：真机连接一副蓝牙耳机（若测试环境无蓝牙耳机 → 标注 **SKIP（无设备）**，不阻塞本轮）。
- **步骤**：
  1. 连上蓝牙耳机，点说话，对**手机麦克风方向**正常说一句「蓝牙路由测试第一句」；
  2. 再对**耳机麦克风**说一句「蓝牙路由测试第二句」；
  3. `dumpsys audio` / logcat 观察输入设备路由（VOICE_COMMUNICATION 常触发 BT SCO 抢占）；
  4. 摘下/断开耳机后再录 1 轮确认回落手机 mic 正常。
- **预期**：两种说法中**至少一路**能正常识别（明确记录实际走哪个 mic）；提示音从哪个设备出声如实记录；断开后回落正常。若出现 SCO 建立导致录音起始明显延迟或整轮无声 → 记录为产品风险。

### R4-014 系统「通话中」状态副作用：并发录音与通知音 P1【须真机·已装包 13:59 版】

- **前置**：提示音开启；准备一个可发出通知音的手段（如另一设备发消息、或 `cmd notification post` 触发默认通知音）。
- **步骤**：
  1. 点说话进入录音态，观察状态栏麦克风指示（正常绿点即可，不应出现「通话中」横幅/通话样式常驻通知）；
  2. 录音中触发一条通知 → 观察通知音是否可闻/被抑制（如实记录）；
  3. 录音中打开系统录音机 App 尝试开始录音（其他 App 并发占用 mic）→ 观察双方行为；
  4. 结束本 App 录音后，验证系统录音机可正常录音（通路无残留占用）；
  5. `appops get <pkg> RECORD_AUDIO` 确认本 App 录音会话随停即止。
- **预期**：
  - 无「通话中」样式系统 UI 常驻；
  - 并发时本 App **不崩溃**：要么继续录、要么优雅失败（回 Idle + 提示），logcat 无 FATAL；
  - 结束后其他 App 录音恢复正常、appops 无活跃残留；
  - 通知音被抑制不判 FAIL，如实记录供产品评估。

### R4-015 模拟器 VOICE_COMMUNICATION 通路可用性 P1【模拟器可测】

- **前置**：AVD wt_real 装同版包；模拟器 mic 指向 Mac 主机音频输入。
- **步骤**：
  1. 点说话开录 3 轮，采集 `first frame after Xms`；
  2. 检查 logcat 无 `start failed`（VOICE_COMMUNICATION 在 AVD 上须能正常 `STATE_INITIALIZED`，谨防出现 vivo UNPROCESSED 式「全零帧」样态）；
  3. 播一句「模拟器通路测试」验证有非零采集（partial 出字或最终有字）。
- **预期**：3/3 起录成功、first frame 正常量级；至少 1 轮出真实文本（模拟器 ASR 精度不作要求，非全零即可）；无异常日志。

## 三、已修项抽验（防音源切换引入回归）

### R4-020 开提示音：喵叫正常播放+无垃圾前缀+850ms 护栏生效 P0【须真机·已装包 13:59 版】

- **前置**：设置中提示音**开启**（R4-001 后记得切换）；清洁链路。
- **步骤**：
  1. 点说话→确认能听到喵叫（音色正常、无破音）；
  2. 等喵叫毕开口说 5 轮标准句（每轮换句）；
  3. 检查每轮首个 partial 与最终文本；
  4. 手点结束时确认结束音成对播出（AudioFlinger writes 开始/结束各一次爆发）。
- **预期**：5/5 无「什么/嗯/所」垃圾前缀（护栏在 VOICE_COMMUNICATION 通路上仍精确遮蔽喵叫窗口——通话通路 AEC 理论上还会削弱自录回声，垃圾前缀应只少不多）；喵叫后停顿不提前触发 endpoint；开始/结束音成对。

### R4-021 幽灵录音兜底：录音中 Home 即停 P1【模拟器可测】

- **前置**：模拟器装同版包；appops 监控就绪。
- **步骤**：点说话进入录音态→ ~1s 后按 Home→10s 内轮询 `appops get <pkg> RECORD_AUDIO`；再唤起键盘验证下一轮起录正常。
- **预期**：Home 后即刻 `stopRecordingAndEndTone: discarded recording, reset to Idle`；mic 会话立即结束（duration 秒级即止，无活跃占用——VOICE_COMMUNICATION 泄漏比 MIC 更敏感，系统可能保持「通信」状态，务必确认释放干净）；无 commit/history 写入；下一轮正常。

### R4-022 endpoint 自动定稿路径 P1【须真机·已装包 13:59 版】

- **前置**：提示音开启；清洁链路。
- **步骤**：说 3 轮完整句后**不点结束**，静默等待自动定稿；记录 `endpoint detected -> auto stop` 时点（相对语音结束）。
- **预期**：3/3 由尾静音自动触发 endpoint（时点在语音结束后 ~2s 量级，对照 R3 中位 ~1.9s 不显著漂移——NS 通路若把尾静音「抹得更干净」可能改变 VAD 判定节奏，漂移 >1s 需记录）；定稿→润色→上屏→写历史全链路正常。

### R4-023 提示音开关即时生效（客观计数）P1【模拟器可测】

- **前置**：模拟器；`dumpsys media.audio_flinger` 基线读数。
- **步骤**：
  1. 提示音开 → 录一轮（含手点结束）→ 读 writes 增量；
  2. 设置关提示音 → 再录一轮 → 读增量；
  3. 再开 → 录一轮 → 读增量。
- **预期**：开轮开始/结束音各一次爆发；关轮 writes **0 增量**（全程无声）；再开恢复；开关状态与 `start(850)` / `start(0)` 护栏联动正确（logcat 或行为佐证：关轮首字不被护栏吞——可播即刻语音验证）。

### R4-024 护栏窗口内手点结束 P2【模拟器可测】

- **前置**：模拟器；提示音开启。
- **步骤**：点说话→ ~400ms 内手点结束（全部样本落护栏窗口内）→ 观察。
- **预期**：ASR 0 字→「未识别到语音」提示→回 Idle；不卡处理中、不上屏、不写历史；开始/结束音成对；下一轮正常起录。

## 四、冒烟

### R4-030 正常语音全链路 P0【须真机·已装包 13:59 版】

- **前置**：提示音开启；默认角色；网络正常。
- **步骤**：说一段带口语冗余的话（「嗯那个我想说的就是这个方案大体上还行但是细节还得再聊聊」）→ 观察字幕流式增长 → 自动定稿 → 润色 → 上屏 → 历史。
- **预期**：partial 流式出字；`polish: success`；commit 上屏为润色文；历史 raw+polished 成对入库；Success→Idle 动画正常；全程无 FATAL/ANR（dropbox 0）。

### R4-031 键盘打字回归冒烟 P0【模拟器可测】

- **前置**：模拟器；系统设置搜索框。
- **步骤**：拼音 `nihao` →选「你好」上屏→ DEL 删字→切英文输 `ab` →数字层输 `12` →猫面板↔打字面板往返→取消返回。
- **预期**：候选/上屏/删除/切层全部正常（搜索框终态可控）；面板往返无布局损坏；无 ANR/crash。
