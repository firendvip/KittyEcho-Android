# 弦外小猫 Android 输入法 · 阶段2 测试用例 · 第2轮（修复验证）

- **被测工程**：KittyEcho-Android（FlorisBoard fork 中文输入法）
- **本轮目标**：定点验证第一轮 5 项 FAIL 的修复 + 修复可能引入的回归面 + 第一轮 PASS P0 冒烟回归。
- **被修复缺陷与实现要点**（用例设计依据，来自当前源码）：
  1. **幽灵录音生命周期兜底**：`FlorisImeService.onWindowHidden` 与 `onFinishInputView` 均调用 `stopVoiceRecordingIfActive()`（不再以 imeUiMode 为条件）；该方法先 `VoiceTrigger.clearPending()`，再经 ViewModelProvider 调 `VoiceViewModel.stopRecordingAndEndTone()`（仅 phase==Recording 时生效，播结束音、释放 AudioRecord、复位 UI；处理中协程不打断），失败兜底直接 `speechEngine.cancel()`。
  2. **VoiceTrigger 改 CONFLATED Channel**：外部入口事件缓存至下一个收集者出现（每事件只消费一次）；连点合并为一次；窗口隐藏时 `clearPending` 丢弃未消费请求。
  3. **模型缺失自愈重装**：`RealSpeechEngine.ensureModelAsync()` 不再只在构造时跑一次——`start()`/`stop()` 发现模型缺失即重新触发，`AtomicBoolean` CAS 防并发重入，跑完复位、失败可重试；进程存活期间自愈。
  4. **切走结束音**：`stopRecordingAndEndTone` 无条件播 endBeep（提示音开启时），保证开始/结束音成对（P2-009c）。
  5. **深色主题取色**：CatKeyboardLayout（面板底/状态文字/字幕/取消药丸 OVERLAY_FG 反色）、ImeToolbar（圆底/图标随深浅）、TextKeyboardLayout（键区前景随深浅）；`onWindowShown` 每次显示时 `themeManager.configurationChangeCounter+1` 重评估 FOLLOW_SYSTEM 主题（缓存命中，代价小）。
- **环境标注**：【模拟器可测】= AVD 即可判定（含 logcat/dumpsys/uiautomator）；【须真机】= 依赖真实语音出字/时序/音质。
- **通用前置**（除非另述）：最新修复版 debug APK 已安装（包名 `com.wordtaker.keyboard.debug`）；已启用并切到弦外小猫输入法；麦克风权限已授予；模型已就位；处于可输入 App 文本框（如系统设置搜索框）。
- **观察手段**：`adb logcat -s VoiceVM RealSpeechEngine VoiceTrigger ModelAssetInstaller ModelDownloader`；麦克风占用 `adb shell dumpsys audio | grep -A3 "MIC"` + `adb shell appops get com.wordtaker.keyboard.debug RECORD_AUDIO`；结束音以 AudioFlinger 混音爆发佐证。

## 一、修复1 定点：幽灵录音生命周期兜底（原 P2-106/P2-110/P2-009c）

### R2-001 录音中按 Home 切走即停录 — P0【模拟器可测】
- **前置**：通用前置；提示音开启。
- **步骤**：点「点击说话」进入录音态 → 按 Home 键回桌面 → 等待 10 秒 → `dumpsys audio` + `appops` 查麦克风占用。
- **预期**：Home 后立即出现 `stopRecordingAndEndTone: discarded recording, reset to Idle` 日志；麦克风 10 秒内无任何活跃 MIC session、appops RECORD_AUDIO 非 running；播放结束音（AudioFlinger 爆发）；不上屏、不写历史。

### R2-002 录音中切到另一 App（焦点切换路径） — P0【模拟器可测】
- **前置**：通用前置；另装任一可输入 App（或用最近任务切换）。
- **步骤**：录音中不按 Home，直接经最近任务切到另一 App 的输入框（触发 onFinishInputView）→ 查麦克风与日志。
- **预期**：切换瞬间停录（onFinishInputView 兜底路径生效）；麦克风释放；结束音播放；新 App 键盘唤起为待机猫面板，无录音残留界面。

### R2-003 录音中锁屏再解锁 — P1【模拟器可测】
- **前置**：通用前置。
- **步骤**：录音中 `adb shell input keyevent 26` 锁屏 → 等 5 秒 → 解锁回原 App 唤起键盘。
- **预期**：锁屏即停录+释放麦克风（锁屏期间 dumpsys 无 MIC 占用）；解锁后键盘为待机态（非录音残留）；可立即开始新录音。

### R2-004 录音中收起键盘（Back/收起键） — P1【模拟器可测】
- **前置**：通用前置。
- **步骤**：录音中按 Back 键（或 `adb shell input keyevent 111` KEYCODE_ESCAPE / 点导航栏收起键盘按钮）收起 IME → 查日志与麦克风 → 再点输入框唤起键盘。
- **预期**：onWindowHidden 兜底触发停录+结束音+麦克风释放；再唤起时默认猫面板待机（imeUiMode 复位 CAT_VOICE）；无幽灵录音。

### R2-005 TEXT 模式下触发的录音切走也要停 — P1【模拟器可测】
- **前置**：通用前置；切到拼音打字面板。
- **步骤**：长按空格触发录音（外部入口）→ 录音态下按 Home 切走 → 查麦克风与日志。
- **预期**：与 R2-001 相同：停录、结束音、麦克风释放（修复点：兜底不再以 imeUiMode==CAT_VOICE 为条件，TEXT 面板发起的录音同样被兜住）。

### R2-006 兜底触发后再次唤起键盘状态干净 — P1【模拟器可测】
- **前置**：通用前置。
- **步骤**：走一次 R2-001（Home 停录）→ 回原 App 点输入框唤起键盘 → 立即点「点击说话」开新录音 → 手点结束。
- **预期**：唤起后为猫面板待机（无残留字幕/电平动画/录音界面）；新录音正常开始与结束（`startRecording phase=Recording` → blank 或出字流程）；两轮之间无状态错乱、无崩溃。

### R2-007 切走结束音对称 + 提示音关闭全静音 — P1【模拟器可测】
- **前置**：通用前置。
- **步骤**：a) 提示音开启：录音中 Home 切走，核对 AudioFlinger 爆发次数；b) 设置中关闭提示音，重复同一路径。
- **预期**：a) 开始音+结束音各一次成对（修复点 P2-009c：切走也播结束音）；b) 全程 0 次爆发（结束音同样受提示音开关约束，`endBeep(toneOn=false)` 静音）。

## 二、修复2 定点：VoiceTrigger CONFLATED Channel（原 P2-011a）

### R2-010 工具栏语音图标触发录音（原 FAIL 主路径） — P0【模拟器可测】
- **前置**：通用前置；键盘处于拼音打字面板，展开工具栏/设置面板。
- **步骤**：点工具栏「语音输入」图标；重复 3 次（每次回待机后再点）。
- **预期**：3/3 次都切到猫面板并**直接开始录音**（logcat 依次 `VoiceTrigger: requestStart` → `VoiceVM: startRecording phase=Recording`）；面板切换期间事件不丢（Channel 缓存至收集者重建后消费）。

### R2-011 连点语音图标合并为一次 — P1【模拟器可测】
- **前置**：同 R2-010。
- **步骤**：以最快速度连点语音图标 5 次 → 观察录音状态与日志 → 手点结束回待机后核对。
- **预期**：只开始**一次**录音（CONFLATED 合并）；录音中后续点击不结束、不重启录音（startFromExternal 仅 Idle 时生效）；结束后**不会**再"补放"一次录音（无排队事件残留）。

### R2-012 clearPending：未消费请求不跨会话 — P1【模拟器可测】
- **前置**：同 R2-010。
- **步骤**：点语音图标后**立即**（<300ms，抢在录音开始前）按 Back 收起键盘 → 等 3 秒 → 重新点输入框唤起键盘。
- **预期**：重新唤起后键盘处于猫面板**待机**，绝不"凭空"自动开始录音（onWindowHidden 已 `clearPending`，日志可见 `VoiceTrigger: clearPending had=true/false`）；麦克风无占用。

### R2-013 CONFLATED 不吞合法二次触发 — P1【模拟器可测】
- **前置**：同 R2-010。
- **步骤**：点图标开始录音 → 点「取消」回待机 → 再次进拼音面板点图标 → 再取消 → 第三次改用长按空格触发。
- **预期**：三次触发**每次都**正常开始录音（每个事件恰好消费一次后 Channel 清空，不存在"第二次被当作重复而吞掉"）；三次取消均正常回待机。

### R2-014 三入口互不干扰 + 录音中触发只开始从不结束 — P1【模拟器可测】
- **前置**：通用前置。
- **步骤**：a) 长按空格触发录音；b) 录音中再长按空格 / 再点工具栏图标（若可达）各一次；c) 取消回待机后短按空格。
- **预期**：a) 正常开始（第一轮已 PASS 的路径不回归）；b) 录音不被停止也不重启（外部入口"只开始、从不结束"语义保持）；c) 短按空格正常上屏空格（长按/短按语义无污染）。CAT_VOICE 键（-214）如仍不在任何布局中，标注不可达即可、不判 FAIL。

## 三、修复3 定点：模型缺失自愈重装（原 P2-205）

### R2-020 进程存活期间删模型可自愈 — P0【模拟器可测】
- **前置**：通用前置；`adb shell run-as com.wordtaker.keyboard.debug rm -rf files/zipformer-zh`（含 `.installed_v2`），**不杀进程**。
- **步骤**：点「点击说话」→ 结束 → 观察提示与 logcat → 等待 ≤60 秒 → 再点「点击说话」→ 结束。
- **预期**：首次触发：不崩溃、出「语音模型正在准备」类提示、`ensureModelAsync` 被重新触发、`ModelAssetInstaller: 模型已从 assets 安装到...` 在**同一进程**内出现（无需重启）；重装完成后第二次语音走通正常流程（blank 或出字）；`files/zipformer-zh/` 4 文件恢复齐全。

### R2-021 重装窗口期连点两次不并发重入 — P1【模拟器可测】
- **前置**：同 R2-020 删除模型。
- **步骤**：删除后**立即**连续两次「点击说话→结束」（间隔 <2s，抢在 ~25s 的 assets 拷贝完成前）→ 观察 logcat 安装日志条数与文件完整性。
- **预期**：安装线程只跑**一份**（CAS 防重入：第二次触发被 `modelInstallRunning` 拦下，无第二条安装开始日志）；两次点击均得到「模型正在准备」提示、不崩溃、不卡死；最终 4 文件完整（encoder ≈70MB，无 `.part` 残留/半截文件）。

### R2-022 start() 路径自愈 + 恢复后全链路 — P1【模拟器可测】
- **前置**：同 R2-020 删除模型。
- **步骤**：删除后点「点击说话」（start() 发现缺失即触发自愈并直接 return）→ 观察此刻 UI 与麦克风 → 等待重装完成 → 完整走一轮录音→结束→回待机。
- **预期**：start() 缺模型时不开录音会话、不占用麦克风、不崩溃（UI 若短暂进录音态也能在结束时正确提示并复位）；重装完成后整轮流程与常态一致，无需进程重启。

### R2-023 半截模型进程内自愈（原 P2-211 免重启变体） — P2【模拟器可测】
- **前置**：通用前置；`run-as` 将 `files/zipformer-zh/encoder.int8.onnx` 截断至 10MB（保留其余文件与 marker），**不杀进程**。
- **步骤**：点「点击说话」→ 结束 → 等待自愈 → 再走一轮语音。
- **预期**：`isDownloaded` 尺寸校验判 false → 进程内自动重装（encoder 恢复 ~70MB）→ 语音恢复；全程无崩溃/闪退循环（第一轮 P2-211 需重启进程才恢复，本轮验证免重启）。

## 四、修复5 定点：深色主题取色（原 P2-303）

### R2-031 FOLLOW_SYSTEM 深↔浅来回切（含窗口隐藏时切换的时序竞争） — P1【模拟器可测】
